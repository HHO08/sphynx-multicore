# المرحلة 6 — إصلاح «Failed initializing CPU or memory» نهائياً + مجلد SYSTEMS_BIOS + الإعدادات والحفظ

**البناء:** `1.18.1-sphynx.3` · armeabi-v7a · 23 كوراً · 35 نظاماً
**التاريخ:** 2026-11-06

---

## 1. سبب المشكلة الحقيقي (وأنا أعتذر: المرحلة 5 عالجت نصفها فقط)

في المرحلة 5 عالجتُ دالة `LaunchFile()`، وهي **مسار «تصفّح الملفات»** فقط. لكن الضغط على لعبة داخل شبكة الألعاب في PPSSPP لا يمر بها إطلاقاً:

```
الضغط على لعبة في الشبكة
   MainScreen::OnGameSelected
        └── GameScreen            (شاشة تفاصيل اللعبة)
              └── GameScreen::OnPlay
                    └── new EmuScreen(path)      ← محرّك PSP مباشرة!
```

`GameScreen::OnPlay` كانت تنشئ `EmuScreen` مباشرة، فيستلم محرّك PSP ملف سوبر نينتندو ويحاول تحميله كأنه ISO بلايستيشن، فيفشل بـ:

> **Could not load game. Failed initializing CPU or memory**

أي أن الإصلاح السابق لم يكن يُنفَّذ أبداً في المسار الذي تستخدمه أنت. هذا هو السبب الذي جعل الرسالة تبقى بعد التحديث.

## 2. ما تغيّر في الإطلاق (7 مواضع + حاجز أمان)

| # | الموضع | كان | صار |
|---|---|---|---|
| 1 | `LaunchFile()` (تصفّح الملفات) | يفحص `IsLocalType()` ثم يُوجّه | صار ينادي دالة واحدة موحّدة |
| 2 | **`GameScreen::OnPlay()`** (الضغط في الشبكة) | `new EmuScreen` مباشرة | **يُوجَّه إلى شاشة التشغيل** |
| 3 | `LogoScreen::Next()` — بعد شعار البداية | `new EmuScreen` | يُوجَّه |
| 4 | `LogoScreen::sendMessage(REQUEST_GAME_BOOT)` | `new EmuScreen` | يُوجَّه |
| 5 | `NativeApp` — فتح لعبة من تطبيق آخر («فتح باستخدام») | `new EmuScreen` | يُوجَّه |
| 6 | `EmuScreen::update()` — **حاجز أخير** | لا شيء | لو وصل الملف إلى محرّك PSP بأي طريق لم أُرقّعه، يُحوَّل فوراً إلى شاشة التشغيل بدل رسالة الخطأ |
| 7 | `Tools/sphynx/check_routing.py` | غير موجود | **يفشل البناء** إذا ظهر أي `new EmuScreen` بلا حماية، أو إذا عاد الشرط القديم `PathType::NATIVE` |

الدالة الموحّدة:

```cpp
bool SphynxRouteExternal(ScreenManager *screenManager, const Path &path) {
	if (!path.IsLocalType())            // ملف عادي أو content://
		return false;
	const std::string sphynxPath = path.ToString();
	if (sphynx_ui_is_external(sphynxPath.c_str()) != 1)
		return false;
	Sphynx_SendCommandToJava("sphynx_launch", sphynxPath.c_str());
	return true;
}
```

**الأهم:** هذا الفحص لا يعتمد على صيغة المسار، ولا يلمس محرّك PSP: ألعاب PSP تمر كما هي بدون أي تغيير.

## 3. مجلد `PSP/SYSTEMS_BIOS`

يُنشأ **تلقائياً عند تشغيل التطبيق** (من C++ في `NativeInit` ومن Java في `NativeActivity.onCreate`)، وداخل مجلد `PSP` نفسه الذي تعرفه:

```
PSP/
├── GAME/
├── SYSTEM/                     ← القديم (يُقرأ أيضاً)
└── SYSTEMS_BIOS/               ← الجديد
    ├── 00-READ-ME-FIRST.txt    (شرح كامل بالعربي والإنجليزي)
    ├── 01-PlayStation/         README.txt
    ├── 02-Sega Saturn/         README.txt
    ├── 03-Sega CD/             README.txt
    ├── 04-PC Engine CD/        README.txt
    ├── 05-Neo Geo CD/          README.txt
    ├── 06-3DO/                 README.txt
    ├── 07-PC-FX/               README.txt
    ├── 08-Amiga/               README.txt
    ├── 09-PC-8801/             README.txt
    ├── 10-PC-9801/             README.txt
    ├── 11-Famicom Disk System/ README.txt
    ├── 12-ColecoVision/        README.txt
    ├── 13-Dreamcast/           README.txt   (اختياري)
    ├── 14-Nintendo DS/         README.txt   (اختياري)
    ├── 15-MSX/                 README.txt   (اختياري)
    └── 16-Master System/       README.txt   (اختياري)
```

**16 مجلداً فقط** — 12 للنظم التي لا تعمل بدون بايوس، و4 للنظم التي تعمل بدونه لكن أفضل معه. أما بقية الأنظمة (19 نظاماً + PSP) فلم يُنشأ لها مجلد إطلاقاً، لأن كوراتها لا تحتاج شيئاً.

### كيف يقرأها التطبيق (بدون أي خطوة إضافية)

1. كل كور يستلم **مجلده الخاص** كـ«مجلد النظام» في libretro (`RETRO_ENVIRONMENT_GET_SYSTEM_DIRECTORY`) — وهذا المكان الوحيد الذي يبحث فيه أي كور عن بايوسه.
2. الأنظمة التي لا تحتاج بايوس تستلم `PSP/SYSTEM` كالسابق.
3. القراءة تحدث **عند كل تشغيل للعبة**، فتستطيع إضافة/تبديل/حذف الملفات في أي لحظة دون إعادة تشغيل التطبيق.
4. أي بايوس موجود مسبقاً في `PSP/SYSTEM` **يُنسخ تلقائياً** إلى مجلده الصحيح (نسخ لا نقل، ولا يُستبدل ملف موجود) — فإعداد PPSSPP القديم عندك يعمل فوراً.
5. المجلدات وملفات `README.txt` تُعاد إنشاؤها إن حذفتها، ولا يُستبدل README عدّلته أنت.
6. إذا لم يوجد ملف صالح: شاشة الخطأ تكتب **اسم النظام + أسماء الملفات الناقصة + مسار المجلد**، وبها زر «BIOS» في قائمة الإعدادات يوضح الحالة دائماً.

## 4. Settings + Save State + Load State

زر **☰** أعلى يمين شاشة التشغيل يفتح:

| العنصر | التفصيل |
|---|---|
| **Save state** | 4 خانات لكل لعبة؛ يُكتب الملف في `files/sphynx/save/states/<اسم اللعبة>.slotN.sav` |
| **Load state** | الخانات الممتلئة فقط تُقبل، والفارغة تُخبرك أنها فارغة |
| **Settings** | الصوت · أزرار اللمس · تسريع · عرض زمن الإطار · فلتر حاد/ناعم · ملاءمة الشاشة (Fit / Stretch / 4:3) · سطر معلومات BIOS |
| **Close game** | إغلاق الشاشة والعودة |

- كل الإعدادات **تُحفظ** في `SharedPreferences` وتُطبَّق في التشغيل التالي.
- ملف الحفظ محمي ببصمة الكور + حجم + **CRC32**، فلا يمكن تحميل حفظ جيم بوي على لعبة سوبر نينتندو، ولا تحميل ملف تالف — والسبب يُكتب بالكلمات.
- ملف الحفظ لا يتعارض مع حفظ PPSSPP الخاص بـPSP: مسار مختلف تماماً.

## 6. الحد الذي لا أستطيع تجاوزه

لا يوجد جهاز أندرويد في بيئتي، فالوصلة الأخيرة (OpenGL + نشاط أندرويد) لم أضغطها بيدي. كل ما فوقها مُختبر آلياً. إن ظهر أي خلل:

- التطبيق **يكتب السبب على الشاشة** (لا شاشة سوداء).
- أرسل لي نص الرسالة أو `logcat` وأصلحه في نفس اليوم.

## 7. التثبيت

1. ثبّت الـAPK فوق النسخة السابقة (نفس التوقيع، لا تحذف شيئاً).
2. افتح التطبيق مرة واحدة → ستجد `PSP/SYSTEMS_BIOS` جاهزاً بالمجلدات.
3. انسخ ملفات البايوس في مجلداتها.
4. اضغط أي لعبة → تعمل في شاشة التشغيل، ومعها ☰ للحفظ والتحميل والإعدادات.
