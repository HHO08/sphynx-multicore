# المرحلة 12 — لا يمكن أن تختفي الأزرار، والشاشة تقول ما تفعله

**النسخة:** `1.18.1-sphynx.12` · **الالتزام:** `44c8d16`

تقول إن الوضع لم يتغيّر بعد نسخة `1.18.1-sphynx.11`. لذلك غيّرت المنهج: لم
أعد أخمّن، بل أزلت كل احتمال أن تكون الأزرار غائبة، وجعلت الشاشة **تعلن عن
حالتها بنفسها** حتى نعرف أين تتوقف بالضبط.

## 1) ثغرة حقيقية في PPSSPP كانت كافية وحدها لإخفاء كل الأزرار

```cpp
// Core/Config.cpp
static bool DefaultShowTouchControls() {
    switch (System_GetPropertyInt(SYSPROP_DEVICE_TYPE)) {
    case DEVICE_TYPE_MOBILE:
        return !KeyMap::HasBuiltinController(System_GetProperty(SYSPROP_NAME));
    default:
        return false;          // ← ليس هاتفاً؟ لا أزرار
    }
}
ConfigSetting("ShowTouchControls", &g_Config.bShowTouchControls, &DefaultShowTouchControls, CfgFlag::PER_GAME);
```

و`CreatePadLayout()` تبدأ بـ:

```cpp
if (!g_Config.bShowTouchControls) {
    return root;      // ← لوحة فارغة: صورة لعبة بلا أي زر
}
```

الإعداد **لكل لعبة** (PER_GAME)، وسقوطه على القيمة الافتراضية ممكن جداً
(جهاز يُعرّف نفسه لا كـ MOBILE، أو ملف إعدادات لكل لعبة من تثبيت قديم).

**التصحيح:** شاشة المشغّل تُفعّل لوحة الأزرار لنفسها فقط إن كانت مطفأة،
وتُعيد إعداد المستخدم كما كان عند الخروج، ولا تكتب شيئاً في الإعدادات.
سياسة PPSSPP نفسها لا تتغيّر خارج شاشة المشغّل.

## 2) سطر حالة على الشاشة — بدل التخمين

في أعلى يسار شاشة اللعب سطر صغير واحد:

```

```

هذا السطر يجيب فوراً عن كل الأسئلة التي لا أستطيع الوصول إليها بلا جهاز:

| ما تقرأه | المعنى |
|---|---|
| الخط ظاهر والأرقام تزيد | المشغّل يعمل والأزرار مطلوبة/مفعّلة |
| `pad OFF` | لوحة الأزرار مطفأة في الإعدادات |
| `pad on(auto)` | كانت مطفأة فأُجبرت على العمل هنا |
| `0x0 · 0 frames` | النواة تعمل لكن لا تُرسل صورة |
| لا ترى السطر إطلاقاً | الشاشة لم تُفتح: المشكلة في التوجيه لا في المشغّل |

## 3) إزالة خطر حقيقي على أجهزة أندرويد (سبب محتمل جداً لـ«القذف»)

كان النسيج (texture) يُنشأ ويُملأ داخل `update()`. PPSSPP لا يفعل ذلك في أي
شاشة من شاشاته: كل لمس للـ GPU عنده داخل `render()`. استدعاء GL خارج تصيير
الإطار على مشغّل رسومات أندرويد قد يُسقط العملية، وسقوط العملية يعني إعادة
تشغيل النشاط = العودة إلى قائمة الألعاب، وهو ما تراه «قذفاً تلقائياً» ولا
يظهر معه أي صندوق خطأ. الآن: `UploadFrame()` من داخل `render()` فقط، وتُتجاهل
إذا لم يكن هناك سياق رسم (بعد العودة من الخلفية).

## 4) تكافؤ في زر إظهار/إخفاء الأزرار

`VIRTKEY_TOGGLE_TOUCH_CONTROLS` صار يعمل في المشغّل بنفس كود `EmuScreen`، فلمسة
واحدة تُعيد لوحة الأزرار الظاهرة بعد اختفائها بالتلاشي.

## 5) ما لم يُلمس

النواة، GPU، HLE، قائمة الألعاب، BIOS، الحفظ، الصور، التوجيه، الترجمة،
الأسرار، الأصول: **لا شيء**. التعديل كله في `UI/SphynxPlayerScreen.{h,cpp}`
وحاجز في `Tools/sphynx/check_routing.py`.
